JWT
JSON Web Token

理解 JWT 的用途、結構、Claims、簽章驗證，以及它與 Authentication、Authorization 的關係。

JWT 不是加密資料的保險箱，而是一份可驗證真偽的身分聲明。

01｜JWT 是什麼？

JWT 是 JSON Web Token 的縮寫，是一種用來安全傳遞聲明資訊的 Token 格式。

🪪

攜帶身分資訊

例如使用者 ID、名稱、角色與其他 Claims。

✍️

透過簽章驗證

API 可以確認 Token 是否由可信任的簽發者產生，以及內容是否被竄改。

🌐

適合跨系統傳遞

常用於 Web API、SPA、行動 App 與分散式系統。

JWT 是一種 Token 格式；Authentication 與 Authorization 則是系統安全流程。

02｜為什麼 Web API 常使用 JWT？

Stateful Session

伺服器保存登入 Session，Client 通常透過 Cookie 攜帶 Session ID。

特性：伺服器需要維護登入狀態。

Stateless Token

Client 每次呼叫 API 時攜帶 Token，API 根據 Token 完成驗證。

特性：較容易支援多個 API 節點與不同類型 Client。

情境JWT 的價值
SPA 呼叫 Web API前端可以在 Authorization Header 中攜帶 Access Token
行動 App不依賴傳統瀏覽器 Session Cookie
多個 API 節點各節點可使用相同規則驗證 Token
微服務可在服務之間傳遞已驗證的身分聲明

03｜JWT 的三個部分

一個 JWT 通常由三段 Base64Url 編碼內容組成，並使用句點分隔。

xxxxx.yyyyy.zzzzz

Header

描述 Token 類型與簽章演算法。

{"alg":"HS256","typ":"JWT"}

Payload

放置 Claims，例如 sub、name、role、exp。

{"sub":"1","role":"Admin"}

Signature

用來驗證 Header 與 Payload 是否遭到竄改。

HMACSHA256(...)
Header 與 Payload 只是編碼，不是加密。任何取得 Token 的人都可能讀取其中內容。

→

→
7. API 驗證 Token
→
8. 執行授權
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
檢查項目目的
Signature確認 Token 沒有遭到竄改
Issuer確認由可信任的簽發者產生
Audience確認 Token 是簽發給目前 API
Expiration確認 Token 尚未過期

05｜Claims 是什麼？

Claim 是對使用者或 Token 的一項聲明。

{
  "sub": "1001",
  "name": "Andy",
  "role": "Admin",
  "department": "IT",
  "exp": 1785187200,
  "iss": "JwtCourseApi",
  "aud": "JwtCourseClient"
}
Claim常見用途
subSubject，識別使用者或主體
name顯示名稱
role角色授權，例如 Admin、Teacher
expToken 到期時間
issToken 簽發者
audToken 的目標接收者
JWT 可以攜帶 Role Claim，但真正的權限判斷仍由 API 的 Authorization 規則負責。

06｜Authentication 與 Authorization

🪪

Authentication

確認使用者是誰，以及 Token 是否有效。

🛡️

Authorization

確認目前使用者是否有權限執行某個操作。

🎭

RBAC

根據 JWT 中的角色 Claim 進行角色授權。

[Authorize(Roles = "Admin")]
[HttpDelete("users/{id}")]
public IActionResult DeleteUser(int id)
{
    return NoContent();
}

07｜JWT 安全觀念

不要放敏感資訊

Payload 可被解碼，不應放密碼、信用卡資訊或其他機密資料。

Access Token 要短效

降低 Token 外洩後可被濫用的時間。

一定要使用 HTTPS

避免 Token 在傳輸過程中被攔截。

驗證 Issuer 與 Audience

避免接受不屬於目前系統的 Token。

妥善保護簽章金鑰

不要將正式金鑰直接提交到 Git Repository。

前端隱藏不是授權

所有敏感操作都必須由後端 API 驗證與授權。

JWT 一旦簽發，通常無法像 Session 一樣立即從伺服器刪除。正式系統需要考慮短效 Access Token、Refresh Token、撤銷與金鑰輪替。

10｜重點整理

JWT 是格式

它用來攜帶聲明資訊，不等於完整的登入系統。

Signature 保證完整性

簽章可以驗證 Token 是否遭到竄改，但不代表 Payload 被加密。

Authorization 仍在 API

Token 提供 Claims，API 根據角色或 Policy 決定是否允許存取。

JWT 負責攜帶與證明身分資訊；API 負責驗證與授權。
