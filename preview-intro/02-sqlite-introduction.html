JWT 課程中的資料儲存選擇

SQLite

理解這個輕量、免安裝、單一檔案的關聯式資料庫，為什麼很適合教學、Demo 與小型應用。

SQLite 不是「假的資料庫」，而是一套嵌入應用程式、直接讀寫檔案的關聯式資料庫。

01｜SQLite 是什麼？

SQLite 是一套輕量級的關聯式資料庫引擎，不需要另外啟動資料庫伺服器。

📄

單一檔案

資料表、索引與資料通常都保存在一個資料庫檔案中。

⚙️

嵌入式資料庫

應用程式直接透過 SQLite 程式庫讀寫資料庫，不需要獨立的 Server Process。

🗃️

關聯式資料庫

支援資料表、SQL、索引、交易與關聯式資料設計。

🗄️
整個資料庫可以放在單一檔案
jwt-course.db

02｜為什麼 JWT 範例使用 SQLite？

快速開始

學員不需要先安裝 SQL Server、建立 Instance 或設定登入帳號。

容易攜帶

專案與資料庫檔案可以一起複製，方便課堂 Demo 與練習。

降低干擾

課程重點放在 JWT、Authentication、Authorization 與 Token 生命週期。

課程選擇 SQLite，是為了降低環境準備成本，不代表正式系統一定應該使用 SQLite。

03｜SQLite 與 SQL Server 的差異

比較項目SQLiteSQL Server
架構嵌入式、直接讀寫檔案獨立資料庫伺服器
安裝通常不需要額外安裝 Server需要安裝或連線到 SQL Server
資料保存常見為單一 .db 檔案由資料庫服務管理資料檔與記錄檔
並行能力適合較輕量的讀寫情境適合大量使用者與高併發
管理功能精簡完整的帳號、備份、監控、HA 等能力
常見用途Demo、測試、桌面 App、小型服務企業系統、正式後端、大型應用
SQLite 與 SQL Server 都能執行 SQL，但兩者並不是完全相同的產品，資料型別、函式、並行與管理能力也不完全一致。

04｜ASP.NET Core 如何使用 SQLite？

在 .NET 專案中，常透過 Entity Framework Core 連接 SQLite。

安裝 Provider

dotnet add package Microsoft.EntityFrameworkCore.Sqlite

連線字串

{
  "ConnectionStrings": {
    "DefaultConnection": "Data Source=jwt-course.db"
  }
}

Program.cs 設定

builder.Services.AddDbContext<AppDbContext>(options =>
    options.UseSqlite(
        builder.Configuration.GetConnectionString("DefaultConnection")));

建立 Migration 與資料庫

dotnet ef migrations add InitialCreate
dotnet ef database update

05｜SQLite 在 JWT 範例中的角色

SQLite 不負責產生 JWT，它負責保存 JWT 流程需要的資料。

使用者資料

帳號、密碼雜湊、名稱、角色與狀態。

Refresh Token

保存 Token 雜湊、到期時間、撤銷時間與輪替關係。

稽核資訊

記錄登入、登出、撤銷或安全事件。

使用者登入
→
從 SQLite 查詢使用者
→
驗證帳號密碼
→
產生 JWT
JWT 通常是由 Token Service 建立；SQLite 則提供使用者、角色與 Refresh Token 等持久化資料。

06｜資料表範例

Users

CREATE TABLE Users (
    Id INTEGER PRIMARY KEY AUTOINCREMENT,
    UserName TEXT NOT NULL UNIQUE,
    PasswordHash TEXT NOT NULL,
    Role TEXT NOT NULL,
    IsActive INTEGER NOT NULL
);

RefreshTokens

CREATE TABLE RefreshTokens (
    Id INTEGER PRIMARY KEY AUTOINCREMENT,
    UserId INTEGER NOT NULL,
    TokenHash TEXT NOT NULL,
    ExpiresAt TEXT NOT NULL,
    RevokedAt TEXT NULL,
    FOREIGN KEY (UserId) REFERENCES Users(Id)
);
正式系統不應直接儲存明文密碼，也不建議直接儲存可使用的 Refresh Token；應保存安全雜湊並妥善管理敏感資料。

07｜SQLite 適合與不適合的情境

適合

課堂範例、Prototype、自動化測試、桌面應用、小型單機工具、低流量服務。

不一定適合

大量同時寫入、高可用需求、複雜權限管理、大型企業後端或需要完整 DBA 工具的系統。

問題判斷方向
是否有大量同時寫入？若有，應評估 SQL Server、PostgreSQL 等伺服器型資料庫。
是否需要高可用與備援？SQLite 本身不是為企業級叢集管理設計。
是否只是課堂 Demo？SQLite 通常非常合適。
是否需要快速複製與重建？單一檔案特性很方便。

10｜重點整理

輕量

不需要獨立資料庫伺服器，環境準備簡單。

單一檔案

方便教學、複製、備份與重建。

仍是關聯式資料庫

支援 SQL、資料表、索引、交易與關聯。

SQLite 適合讓課程聚焦在 JWT，而不是讓學員先花時間建置資料庫伺服器。
