Refresh Token
更新權杖機制

讓 Access Token 保持短效，同時讓使用者不必頻繁重新登入。

Access Token 負責短期存取；Refresh Token 負責在受控條件下換發新的 Access Token。

01｜只有 Access Token 會遇到什麼問題？

Access Token 設很久

使用者體驗較好，但 Token 外洩後，攻擊者可使用較長時間。

安全風險較高。

Access Token 設很短

安全性較好，但使用者可能頻繁遇到登入失效。

使用體驗較差。

Refresh Token 的目的，就是在「短效安全」與「使用者體驗」之間取得平衡。

02｜Access Token 與 Refresh Token

比較項目Access TokenRefresh Token
主要用途呼叫受保護 API換發新的 Access Token
生命週期通常較短通常較長
傳送位置常放在 Authorization Header只送到專用 Refresh Endpoint
是否包含 Claims通常會包含常為高熵隨機字串，不必是 JWT
是否應保存於資料庫通常不必逐筆保存通常應保存雜湊與狀態
外洩影響在有效期內可呼叫 API可能被用來持續換發 Token
Refresh Token 不一定要使用 JWT。常見做法是產生不可預測的隨機字串，再於資料庫保存其雜湊。

04｜Refresh Token Rotation

每次使用 Refresh Token 時，都換發一個新的 Refresh Token，並立即讓舊的失效。

Refresh Token A
→
換發 Access Token 2
+
Refresh Token B
Refresh Token A 撤銷
→
只允許 Token B 繼續使用
Token Rotation 可降低單一 Refresh Token 長期有效的風險，也能協助偵測 Token 重複使用。

05｜Reuse Detection：重複使用偵測

若一個已經被輪替或撤銷的 Refresh Token 再次出現，可能代表 Token 已遭竊取。

正常情況

Client 使用 Token A，伺服器換發 Token B，之後只使用 Token B。

Token A 不會再次出現。

可疑情況

Token A 已經被使用過，但稍後又有人拿 Token A 來換發。

可能是攻擊者使用外洩 Token。

偵測到重複使用時，可撤銷整個 Token Family，要求使用者重新登入。

06｜資料庫應保存哪些資訊？

Refresh Token 通常需要持久化，以支援撤銷、輪替與稽核。

CREATE TABLE RefreshTokens (
    Id INTEGER PRIMARY KEY AUTOINCREMENT,
    UserId INTEGER NOT NULL,
    TokenHash TEXT NOT NULL,
    ExpiresAt TEXT NOT NULL,
    CreatedAt TEXT NOT NULL,
    RevokedAt TEXT NULL,
    ReplacedByTokenId INTEGER NULL,
    TokenFamilyId TEXT NOT NULL,
    FOREIGN KEY (UserId) REFERENCES Users(Id)
);
欄位用途
TokenHash保存 Refresh Token 的雜湊，不直接保存可使用的明文 Token
ExpiresAtRefresh Token 到期時間
RevokedAt撤銷時間，若有值表示不可再使用
ReplacedByTokenId記錄輪替後的新 Token
TokenFamilyId追蹤同一登入工作階段的 Token 系列
資料庫外洩時，若保存的是明文 Refresh Token，攻擊者可能直接使用；因此應優先保存雜湊。

08｜安全設計重點

Access Token 短效

縮短外洩後可被使用的時間。

Refresh Token 高熵

使用安全亂數產生，不可預測。

資料庫保存雜湊

避免資料庫外洩後可直接使用 Token。

啟用 Rotation

每次換發都讓舊 Refresh Token 失效。

支援撤銷

登出、密碼變更或帳號停用時撤銷 Token。

只使用 HTTPS

避免 Token 在傳輸過程中遭到攔截。

Refresh Token 的保存方式會影響 CSRF 與 XSS 風險。若放在 HttpOnly Cookie，需考慮 SameSite、Secure 與 CSRF 防護；若交給 JavaScript，則需特別防範 XSS。

09｜登出與撤銷

事件建議處理
使用者登出撤銷目前 Refresh Token 或整個 Token Family
密碼變更撤銷使用者現有的 Refresh Tokens
帳號停用拒絕所有後續換發，並撤銷有效 Token
疑似 Token 外洩撤銷整個 Token Family，要求重新登入
登出通常無法讓已簽發的 Access Token 立刻消失，因此短效 Access Token 仍然很重要。

12｜重點整理

Access Token

短效，用來呼叫受保護 API。

Refresh Token

較長效，只用來換發新的 Token Pair。

Rotation 與撤銷

降低外洩風險，並提供安全事件處理能力。

Refresh Token 不是讓 Token 永遠有效，而是讓重新簽發這件事可以被控管、追蹤與撤銷。
